## Known limits & follow-ups

- `entity_edges` SVO triples: the LLM extractor produces entity *mentions*
  for short sentences but rarely full Subject-Predicate-Object relations,
  so `entity_edges` count for our test user stays at 0. F11 invalid_at
  bookkeeping is therefore exercised on `memory_edges` (where it works
  cleanly), but the `entity_edges` codepath only sees production data
  from longer multi-fact ingests. Not a regression — the code is wired
  through `entityLinkPair.invalidAt` and `EdgeValidity` for both
  `add_episodic.go:linkHandlerPair` and `reorganizer_entities.go:linkOnePair`.
- F11 edge_judge metric `outcome="no_peers"` (count 2) confirms the judge
  is firing for the contradiction ingest ("until December 2023, then
  Globex on January 1, 2024") but finds no entity_edge peers to overwrite.
  The cross-record contradiction was instead captured by the standard
  ADD/UPDATE pipeline: the original Acme `memory_edge` had its `valid_at`
  re-stamped from `2023-10-18 → 2023-12-01` automatically.
- Historical corpus (16 373 rows) lacks event_dates because they were
  ingested before today's extractor changes. Re-extraction is a 4-hour
  LLM job — out of scope per CLAUDE.md eval policy. A future migration
  job should re-run the F3 extractor over the unconverted rows in
  cube-by-cube batches and write event_dates / user_events without
  recomputing embeddings.
- `memdb_scheduler_loop_iterations_total{name="bitemporal_validator"}`
  is 0 success + 1 measurement bucket — the validator is wired but only
  runs when `MEMDB_F11_VALIDATOR_ENABLED=true` (currently disabled, as
  intended; sync-path edge_judge is sufficient).

## Conclusion

F3 and F11 are operational on the prod write path and the search/chat read
path. New ingests stamp `event_dates`, persist `user_events`, set
`memory_edges.valid_at`, and let the search stage inject events into the
candidate pool. Chat answers temporal questions correctly. The
contradiction-judge codepath is wired and metric-emitting; it is dormant
on entity_edges only because the extractor leaves entity SVO triples
empty for short factual sentences (mentions are written instead). The
remaining gap is historical-corpus backfill, deferred by user policy.
