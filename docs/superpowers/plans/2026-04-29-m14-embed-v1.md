# M14 — `go-kit/embed` v1.0.0 (Production-Grade Embed Library)

> **Status**: BACKLOG (not active). Park until M13 integration of M12.10 rerank features in memdb-go is complete and embed-server load patterns settle.
>
> **Mission**: bring `go-kit/embed` (extracted into go-kit at v0.28.0, 2026-04-28) to feature parity with `go-kit/rerank` (which closed M12.10 at v0.29.0). embed currently lacks: functional options, Result type, Observer hooks, circuit breaker, multi-model fallback, auto-batching, dedup-in-batch, cache interface, token usage tracking. All of these have proven analogues in rerank — copy patterns, adapt to embed-specific concerns.
>
> **Driver**: embed library is the dual to rerank in the search pipeline (bi-encoder retrieval). Same caller (memdb-go) uses both. Inconsistent API surface across the two = constant cognitive overhead. Bringing embed up to rerank's standard halves caller mental load.
>
> **Mode**: subagent-driven development, same discipline as M12.10. 5 streams (E0-E4), each = implementer + spec reviewer + code-quality reviewer.

## Current state (post-PR #6 + #7, v0.28.0 baseline)

**Files** (`~/src/go-kit/embed/`, ~1970 LOC + onnx subpkg):
```

factory.go     — New(cfg, logger) Embedder, dispatches on Config.Type
config.go      — flat Config{} struct, 8+ fields
http.go        — HTTPEmbedder (OpenAI-shape)
ollama.go      — OllamaClient (with prefix opts, the only backend with real Opts)
voyage.go      — VoyageClient (hosted Voyage AI)
retry.go       — withRetry generic helper, hardcoded defaultRetry
registry.go    — Registry for multi-model setup
metrics.go     — embed_requests_total, retry_reason
normalize.go   — L2Normalize helper
onnx/          — separate cgo subpackage (libonnxruntime + libtokenizers)
```

**4 backends**: HTTP, Ollama, Voyage, ONNX (cgo, separate import).

**What works**:
- 4-backend factory pattern
- Registry for `/v1/embeddings` with multi-model
- Retry with exp backoff (200ms → 400ms → 800ms, 3 attempts)
- L2 normalize helper (post-embed)
- Prometheus metrics: requests + retry reason
- Health A grade (92/100), no cycles, 0 vuln deps

**Verified gaps** (caller `memdb-go/internal/server/server_init.go` shows the friction):
- No functional options — every backend has different Opt pattern (Ollama has `OllamaOption`, HTTP/Voyage don't)
- No Result type — caller can't distinguish degraded from skipped
- No Observer hooks — only `slog` + metrics. Caller can't wire custom tracing/quota
- No circuit breaker — embed-server saturated → 30s timeout × N concurrent = cascade failure
- No multi-model fallback at client level — caller writes its own retry-with-different-model loop
- No cache interface — same `(model, text)` re-embed, ~10-30% redundant compute on chat memory ingest
- No auto-batching — Voyage 128 limit hit, caller must split
- No dedup-in-batch — duplicate texts (commit messages, repetitive logs) compute N times
- No Matryoshka dim truncation — pgvector storage 2-4× larger than necessary
- No token counting — Voyage/OpenAI return usage; caller can't track budget
- No model-aware instruction prefix — caller must know per model

## Stream E0 — Foundation: Options + Result + Hooks (1 day, ★★★★★)

**Goal**: replace flat `Config{}` with functional options. Add typed `Result`. Wire `Observer` interface with safeCall panic-safe dispatch. Foundation for E1-E4.

### Files (4 NEW + 1 EDIT)

- `config.go` (~120 LOC, EDIT) — `cfgInternal` private struct + `Opt = func(*cfgInternal)`. Backends share common config.
- `result.go` (~50 LOC) — `Result{Vectors []*Vector, Status, Model, TokensUsed, Err}` + `Status` enum.
- `hooks.go` (~80 LOC) — `Observer` interface + `noopObserver` + `safeCall` wrapper.
- `client_v2.go` (~80 LOC) — `NewClient(url string, opts ...Opt) *Client` + `EmbedWithResult(...) (*Result, error)`.
- `client.go` (NEW, ~100 LOC) — generic Client wrapping any backend by URL convention; v1 backend types kept as aliases.

### API surface

```go
// Result is the typed return for EmbedWithResult.
type Result struct {
    Vectors    []*Vector  // per-text result; len == len(input texts)
    Status     Status     // Ok | Degraded | Fallback | Skipped
    Model      string     // resolved model name
    TokensUsed int        // sum across batch (0 if backend doesn't expose)
    Err        error      // non-nil iff Status == Degraded
}

type Vector struct {
    Embedding []float32
    Dim       int       // == len(Embedding)
    TokenCount int      // per-text, 0 if backend doesn't expose
    Status    Status    // per-text: Ok | Degraded | Skipped (for partial-batch failure)
}

type Status uint8
const (
    StatusOk Status = iota
    StatusDegraded
    StatusFallback
    StatusSkipped
)

// Observer hooks — same panic-safe dispatch pattern as rerank G0.
type Observer interface {
    OnBeforeEmbed(ctx, model string, n int)
    OnAfterEmbed(ctx, status Status, dur time.Duration, n int)
    OnRetry(ctx, attempt int, err error)
    OnCircuitTransition(ctx, from, to CircuitState)
    OnCacheHit(ctx, n int)
    OnTruncate(ctx, textIdx int, beforeTokens, afterTokens int)
}

// Functional options.
type Opt func(*cfgInternal)

func WithModel(string) Opt
func WithDim(int) Opt                    // E4: matryoshka truncation
func WithTimeout(time.Duration) Opt
func WithMaxBatchSize(int) Opt           // E2: auto-split threshold
func WithConcurrency(int) Opt            // E2: parallel batch fan-out
func WithRetry(RetryPolicy) Opt          // E1
func WithCircuit(CircuitConfig) Opt      // E1
func WithFallback(*Client) Opt           // E1
func WithCache(Cache) Opt                // E3
func WithObserver(Observer) Opt          // E0
func WithHTTPClient(*http.Client) Opt    // E0
func WithDocPrefix(string) Opt           // E4 (was Ollama-specific)
func WithQueryPrefix(string) Opt         // E4

// Per-call options.
type EmbedOpt func(*embedCallCfg)
func WithDocMode() EmbedOpt              // applies WithDocPrefix to this call
func WithQueryMode() EmbedOpt            // applies WithQueryPrefix to this call
func WithDryRun() EmbedOpt               // skip HTTP, return zeros
```

### v1 compat

`func New(cfg Config, logger *slog.Logger) (Embedder, error)` kept verbatim. Internally translates Config → opts. `TestV1ApiUnchanged` pins all existing factory_test, http_test, ollama_test, voyage_test fixtures byte-identical.

### Tests

## Stream E2 — Auto-batching + Dedup-in-batch (2 days, ★★★★★)

**Goal**: caller stops manually splitting batches. Library knows backend `MaxBatchSize` and splits + parallel + dedups in-batch. **Real value** — every caller currently writes this loop.

### Files (1 NEW + 1 EDIT)

- `batch.go` (~250 LOC):
  - `splitBatch(texts, maxSize) [][]string` — pure helper
  - `dedupTexts(texts) (uniqueTexts []string, expandIdx []int)` — text → unique index, preserving original order on expansion
  - `EmbedBatched(ctx, e Embedder, texts, opts...) ([]*Vector, error)` — orchestrator: dedup → split → parallel → expand → merge
- `client.go` (extended) — `Embed` now calls `EmbedBatched` internally if `cfg.maxBatchSize > 0` AND `len(texts) > maxBatchSize`. Otherwise direct call (v1 path).

### Behavior

```go
e := embed.NewClient(url,
    embed.WithMaxBatchSize(128),   // Voyage limit
    embed.WithConcurrency(4),      // parallel HTTP calls
)

// 5000 texts. Library auto-splits into ~40 batches × 128, runs 4 in parallel,
// dedups identicals before send (saves N×compute on chat-memory loads),
// merges results in input order.
vecs, _ := e.Embed(ctx, hugeBatch)
```

### Metrics
```
embed_batch_split_total{backend} counter — how often we split
embed_batch_dedup_ratio histogram — unique/total ratio per call
embed_concurrent_batches gauge — current parallel
```

### Tests
- `batch_test.go`: split correctness on edge cases (empty, single, exact multiple); dedup with realistic chat-memory fixtures (~20% dup rate); parallel under -race; preserves input order on expansion

## Stream E3 — Cache (interface only, 0.5 day, ★★★★)

**Goal**: pluggable `Cache` interface, zero impl in go-kit. Caller wires Redis/LRU/sync.Map. Mirror rerank G4 cache discipline.

### Files (1 NEW)

```go
// cache.go (~80 LOC)
type Cache interface {
    Get(ctx context.Context, key string) ([]float32, bool)
    Set(ctx context.Context, key string, vec []float32)
}

func WithCache(c Cache) Opt

// cacheKey computed as sha256(model + "\x00" + dim + "\x00" + docPrefix + "\x00" + queryPrefix + "\x00" + text).
// Includes prefix because text-with-prefix produces different embeddings (e5 family).
// Includes dim because Matryoshka truncation changes output (E4).
func cacheKey(model string, dim int, docPrefix, queryPrefix, text string) string
```

### Wire in `client.go::Embed`

Cache check **before** auto-batching split:
- For each text, lookup `cacheKey` in Cache
- Collect cache misses → batch them
- Cache hit → vector returned directly without HTTP
- After successful batch return → `Cache.Set` per text

Fire `OnCacheHit(ctx, n)` Observer hook with hit count.

### Tests
- Cache key determinism + per-prefix + per-dim differentiation
- Full-batch hit short-circuits HTTP (mock server call counter)
- Partial hit only batches misses (verify HTTP request body has only miss texts)

## Risk + mitigation

| Risk | Mitigation |
|------|-----------|
| Refactoring freshly-extracted package introduces regressions | TestV1ApiUnchanged invariant per stream; spec reviewer enforces v1 contract on every PR |
| Adding circuit breaker breaks low-load callers used to "instant fail" | Default circuit OFF (opt-in only); CHANGELOG flags retry-on-default-now-true (mirrors rerank G1 caller-impacting default) |
| Auto-batching adds latency on small inputs | `MaxBatchSize=0` (opt-in default = no auto-split); preserves direct-call fast path |
| Cache key includes too many fields → cache pollution | sha256(model+dim+prefix+text) — comprehensive but per-tuple deterministic; document invalidation path |
| Stream conflict in client.go pipeline | Serial merging; controller verifies post-merge state on each stream; reject if v1 baseline broke |
| Embed-server sensitivity to bigger batches (auto-batching can saturate) | Default Concurrency=1; metric `embed_concurrent_batches` exposes current load; operator opts in to higher concurrency |

## Out of scope (M15+)

- **gRPC backend** — TEI supports it, faster than JSON. Defer until measured benefit on prod load.
- **Streaming embed** — for huge batches, stream chunk-by-chunk. Complex client API; defer.
- **Cross-encoder integration in same library** — keep separation: embed = bi-encoder, rerank = cross-encoder.
- **Custom Embedder impls** (FAISS adapter, SentenceTransformers Go bindings) — caller concern, not library.
- **Token-budget rate limiter** — caller wires via Observer.OnBeforeEmbed.
- **Sentence boundary chunking helper** — text-prep concern, not embed concern. Could live in separate `go-kit/textprep` package later.

## Open questions

1. **Should `WithFallback` accept a list `[]Embedder` for chained fallback (primary→A→B)?** Rerank G1 only has single fallback. Decide during E1 design.
2. **Does Matryoshka truncation work uniformly across all backends?** OpenAI/Voyage support `dim` query param. Ollama doesn't (always full-dim). Document per-backend behaviour or implement client-side fallback truncation+renormalize.
3. **Should auto-prefix apply only to `WithDocMode()`/`WithQueryMode()` per-call opts, or always when model is known?** Implicit-prefix surprises callers; explicit-mode requires opt-in. Probably explicit-mode for safety (mirror rerank's default-empty instruction prefix).
4. **Should Cache key include `Concurrency` or batching params?** No — those are transport, not output-affecting. Document.
