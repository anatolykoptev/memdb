## Per-variant procedure

For each variant:

1. **Set env** in `~/deploy/krolik-server/.env`:
   ```bash
   MEMDB_RERANK_MATH_PREFILTER=<A1>
   MEMDB_RERANK_MATH_LAMBDA=<lambda>
   MEMDB_CE_PRECOMPUTE_MATH_PREFILTER=<B1>
   MEMDB_CE_PRECOMPUTE_COSINE_THRESHOLD=<thresh>
   MEMDB_RERANK_CIRCUIT=<M15>
   ```
2. **Restart memdb-go** (env reload):
   ```bash
   cd ~/deploy/krolik-server && docker compose up -d --no-deps --force-recreate memdb-go
   sleep 8
   ```
3. **Verify env injected**:
   ```bash
   docker exec memdb-go env | grep -E '^MEMDB_(RERANK|CE_PRECOMPUTE)' | sort
   ```
   Compare to expected — abort variant if mismatch.
4. **Run** the eval (skip ingest if already done):
   ```bash
   cd /home/krolik/src/MemDB/evaluation/locomo
   LOCOMO_FULL=0 LOCOMO_CATEGORIES=1,2,3,4,5 \
     OUT_SUFFIX=ab-V<N>-<short-config> \
     ./run.sh 2>&1 | tee /tmp/ab-V<N>.log
   ```
   Note: harness does its own ingest; on shared 50-QA sample re-ingest is fast (~30s) and clean. Acceptable.
5. **Snapshot metrics** post-run:
   ```bash
   curl -sf http://127.0.0.1:8080/metrics | grep -E 'math_prefilter|ce_precompute_math|rerank_circuit|rerank_chain|llm_judge|search_duration' > /tmp/ab-V<N>-metrics.txt
   ```
6. **Save outputs**:
   - `evaluation/locomo/results/predictions-ab-V<N>-<config>.json` (auto by harness)
   - `evaluation/locomo/results/ab-V<N>-<config>.json` (auto by harness)
   - `/tmp/ab-V<N>-metrics.txt` (post-run metrics snapshot)
   - `/tmp/ab-V<N>.log` (full run log)

## Final analysis

After all 6 variants:

1. **Comparison table** in markdown:
   - Per-cat LLM Judge for each variant
   - Aggregate (excl cat-5) LLM Judge
   - hit@K
   - F1
   - Total runtime per variant
2. **Find best variant** — highest LLM Judge headline (excl cat-5).
3. **Flag deltas worth investigating**:
   - Per-cat regressions (anywhere a variant is worse than V0/V1 baseline)
   - hit@K vs LLM Judge gap shifts (is A1 reducing the refinement gap?)
   - Latency tail (variant with worst p99)
4. **Surface bugs / tuning opportunities**:
   - M15 metrics: `rerank_circuit_state` should be `closed` throughout — if it transitions, document.
   - A1 metrics: `math_prefilter_engaged_total` should be > 0 in V2/V3/V4/V5 — if not, A1 didn't fire (env mis-injected or wiring bug).
   - B1 metrics: `ce_precompute_math_skipped_total` after scheduler tick — confirm filter operates.
   - Any ERROR-level memdb-go logs during run.
5. **Recommendation** — concise: "best variant = V_X, lambda = X, deploy as default in `~/deploy/krolik-server/.env`. Defer Y because Z."

## Hard rules

- **NO full-corpus run.** Only `LOCOMO_FULL=0` sample. User explicitly forbids.
- **Restore env after sweep** — final state should match V5 (all ON, the recommended config) OR the original V1 if recommendation defers A1. Document what was set at the end.
- **NEVER silently disable** — if a variant produces ERROR-level logs, surface, don't filter them out of the report.
- **No code changes** — this is pure measurement. If you find a bug that needs code, file a follow-up task description in the report (do NOT fix in this run).
- **Keep memdb-go running** after sweep — running on prod, must not be left in down state.
- **Serial only** — variants must run sequentially because they share the same memdb-go instance and conflicting env. Parallel is not safe.
