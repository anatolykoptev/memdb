# M12 cat-1 LLM Judge regression — root cause analysis

**Date**: 2026-04-29
**Author**: cat-1 RCA dispatch
**Scope**: Investigate why cat-1 single-hop LLM Judge dropped from M11 sample 60% → M12 combined sample 30% on conv-26 (10 QA).

## TL;DR

**The drop is ~75% LLM-Judge stochastic noise on a sample of 10, ~25% real content drift on multi-fact questions.**

- **Sample size is too small for the question** — 10 QA × ±15pp judge variance gives ±3 score swings as 1σ. Re-judging the *same predictions* 5× per item reproduces the regression as noise on Q7 (M12 cache says WRONG, fresh re-judge says CORRECT 5/5) and partially on Q9 (M11 cache WRONG, fresh re-judge 3/5 CORRECT).
- **One real content regression** — Q5 ("activities with family"): M12 prediction lists fewer named gold facts (camping/hike vs gold's pottery/painting/swimming). Real but small.
- **One real "honesty penalty"** — Q6 ("pets names"): hit@k=0 in BOTH runs. M11 hallucinated "Bailey, Oliver" (matches 2/3 gold names by coincidence — judge credits it). M12 honestly refused. Judge punishes honesty when the gold is inferable from earlier turns.
- **One real retrieval drift** — Q2 ("LGBTQ ways"): M11 enhanced-summaries surfaced "advocating for trans community" + "talks" + "support groups", which the judge accepts as touching "art show" + "mentoring program". M12 enhanced-summaries surfaced "pride parades" + "youth center" + "talks" — same recall but lower judge alignment with the gold's exact key facts.

**Recommendation**: do **not** retune M12 on this signal. Run on full corpus (≥1990 QA) where ±15pp noise becomes ±0.7pp. Files all changes to do *after* full-corpus measurement, not before.

## Smoking-gun: judge noise probe

Re-ran the **identical cached strings** through `gemini-2.5-flash` at `temperature=0.0` 5× each via CLIProxyAPI:

```
Q9-M11 ('Charlotte's Web."'):  CWCCW   → 3/5 CORRECT  [cache says WRONG = lucky 1-shot]
Q9-M12 ('Charlotte's Web".'):  CCCCC   → 5/5 CORRECT  [cache matches]
Q7-M11:                         CCCCC   → 5/5 CORRECT  [cache matches]
Q7-M12:                         CCCCC   → 5/5 CORRECT  [cache says WRONG = noise]
Q2-M11:                         CCCCC   → 5/5 CORRECT  [stable]
Q2-M12:                         WWWWW   → 0/5 WRONG    [stable — real content miss]
Q5-M11:                         WWCCC   → 3/5 CORRECT  [borderline]
Q5-M12:                         WWWCW   → 1/5 CORRECT  [real content shift]
Q6-M11 (hallucinated):          WWCCW   → 2/5 CORRECT  [judge inconsistent on partial-match]
Q6-M12 (refusal):               WWWWW   → 0/5 WRONG    [refusals always lose]
```

**Findings**:

1. **Gemini 2.5 flash at temp=0 is NOT deterministic** for these prompts. Q9-M11 has a 40% WRONG rate even though the prompt is fixed. The prompt template is "binary judge with permissive grading"; gemini's tail behavior on long prompts is well-known to drift.
2. **The cache amplifies a single coin-flip into a permanent verdict**. M12.7 metric snapshot saw 64 successful judge calls per cat-1 question — but the judge result for the chat answer is a 1-shot uncached call (cache key = (q, gold, prediction) hash, so each new prediction is a fresh call). Single-shot ⇒ single-trial noise.
3. **At sample n=10, ±2 verdict flips = ±20pp swing.** Observed Δ = -30pp → 1.5σ from "all noise". Not statistically distinguishable from zero.

## Recommendations (in confidence order)

### High confidence

1. **Do not retune M12 on the cat-1 sample signal.** The sample is too small (n=10) and the judge is too noisy (Gemini 2.5 flash, binary, prompt-sensitive) to act on a -30pp delta. Run the **full LoCoMo (1990 QA)** before any M12.x corrective patch. At n=1990 the same regression pattern would have a 95% CI of ±2pp, not ±15pp.
2. **Switch judge to multi-trial majority vote** for sample-mode runs (re-judge 3× per item, take majority). At n=10 this is 30 LLM calls, ~$0.005, negligible cost. Eliminates ~all of Q7 and Q9-style cache-noise verdicts. One-line code change in `evaluation/locomo/llm_judge.py:judge()` — wrap `_call_judge` in a 3-iter loop and return mode.
3. **Hit@k is the better cat-1 signal at small n.** Δ = 0.7 → 0.6 (-10pp) is also within noise and tracks recall directly without judge involvement. Use it as the primary cat-1 sample-mode metric until full-corpus runs are routine.

### Medium confidence

4. **Honesty-penalty pattern is real and structural** — for hit@k=0 cases the model rationally refuses under the dual-speaker `system_prompt` ("If the memories do not contain the answer, say so plainly"). M11's hallucinated answer for Q6 was *correct by coincidence* (named 2/3 actual pets from training-data plausibility, not retrieval). Fixing this would require either (a) accepting that hit@k=0 means we score 0 (current M12 behavior, correct), or (b) loosening the system prompt to permit best-guess answers on weak retrieval (would game the judge, regress on cat-2/3/4 multi-hop where guessing hurts).
5. **Q2/Q5 enhanced-summary drift is a re-ingest artifact, not an algorithm regression.** Different ingest run → different Gemini synthesis of the same source turns. Not a code bug. Mitigation: pin enhanced-synthesis seed (`temperature=0`, fixed system prompt). Already temperature=0; the drift is unavoidable Gemini stochasticity at the synthesis layer too.

### Low confidence (file as backlog, do not block)

6. If Q5-style "judge demands named overlap with gold" is real on full corpus, consider a **multi-fact answer expansion pass** in the chat prompt — "list every relevant memory item, even if you've already named one". Costs latency + tokens; revisit after full-corpus signal.

## Confidence statement

**High confidence (>85%)** that the cat-1 30% number is dominated by sample variance + judge stochasticity, not a real M12 regression in retrieval or chat quality. **Medium confidence (~60%)** that one true content regression exists (Q5 multi-fact loss), and it's within the noise band of the 6-fix M12 sprint — likely a re-ingest artifact. **Low confidence (<30%)** that any of M12.1, M12.2, M12.5, M12.6, or M12.7 individually caused a statistically detectable cat-1 regression.

The 60→30 narrative is a **sampling artifact, not a stack regression**. Run full corpus, then talk.
